## 工作内容

### R8.x.9 — subagent capability scoping + audit log

Closed the R8.x.9 minimum viable scope on top of the R8.x.6/R8.x.7
delegation + worker foundation. The new surface has three pieces:

1. **Closed capability allowlist** (`packages/runtime/src/delegate-runtime.ts`)
   - Exports `ALLOWED_CAPABILITIES` (6 entries: `general`,
     `get_current_time`, `summarize_today`, `recall_history`,
     `read_file`, `run_command`) + `AllowedCapability` type.
   - The existing `Capability`/`DelegateInput` shape is unchanged so
     downstream consumers stay type-compatible.

2. **Route-layer enforcement** (`apps/api/src/tools.ts`)
   - `makeDelegateToSubagentTool.run` now reads
     `args["capabilities"]` as `string[] | undefined`, defaults to
     `["general"]` if absent, and rejects any value not in
     `ALLOWED_CAPABILITIES` with an envelope
     `{ ok: false, reason: "invalid capability: X (allowed: ...)" }`.
   - On rejection, calls `appendAudit({ kind: "rejection", reason })`
     before returning the envelope.
   - On success, calls `appendAudit({ kind: "delegation", ... })`
     with the resolved capability set + new childConversationId.
   - `WEIBUTLER_LLM_TOOLS[].parameters` for `delegate_to_subagent`
     now advertises the optional `capabilities` array so the LLM
     knows it can specify it.

3. **Worker defensive check + completion audit** (`apps/api/src/subagent-worker.ts`)
   - Reads `payload.capabilities` from each outbox `Delegate` message.
     If any entry is not in the allowlist, logs + writes a
     `rejection` audit row + returns without calling the LLM (the
     outbox message is still marked delivered so it does not retry
     forever).
   - On the normal success path, after
     `bridge.appendConversationEvent(...)`, writes a `completion`
     audit row with `replyExcerpt: result.content.slice(0, 200)`.

### Audit log module (`apps/api/src/audit-log.ts`)

New ~60-line module that writes one JSON line per entry to
`~/.butler/audit/subagent-r8x9.jsonl`. Key properties:

- All filesystem calls are wrapped in try/catch so a broken
  filesystem cannot kill the route or worker.
- Path is computed lazily via `process.env["HOME"] ?? homedir()` so
  tests can override HOME between cases.
- `AuditEntry` type is `readonly` throughout (no mutation).
- No `throw`, no `// ts-prune-ignore-next`.

### System prompt update (`apps/api/src/wechat-inbound-llm.ts`)

The `delegate_to_subagent` description now reads:

```
delegate_to_subagent(task, role?, capabilities?): delegate a task to a
subagent (runs in background, returns later). Use when the user's
request requires capabilities you don't have. Optional `capabilities`
is an array of strings from the allowlist (general, get_current_time,
summarize_today, recall_history, read_file, run_command); defaults to
['general'] if unspecified.
```

## 已知偏差与待办

- **Audit log writes to `~/.butler/audit` only** — no logrotate, no
  size cap, no shipping to a SIEM. Owner-facing in next session.
- **Allowlist is closed (6 entries)** — future capability additions
  require code change, not config. Acceptable for R8.x.9 MVP.
- **Worker defensive check still trusts outbox shape**: a malformed
  payload with non-string `capabilities` entries gets coerced to `[]`
  via `Array.filter((c): c is string => typeof c === "string")`, so
  the worker would fall through to the LLM with an empty
  capability set. Acceptable for now since the route layer already
  filters strings before enqueue.
