## Rollback trigger（owner 决策：2026-08-12）

**Trigger rollback if ANY of:**
- v5 error rate **> 2%** sustained 5+ minutes
- v5 p99 latency **> 2x** v4 p99 baseline sustained 5+ minutes
- Critical path failure（auth / core API endpoints 返回 5xx）

**Decision criteria per phase（基于 error rate / latency）:**
- Proceed: v5 error rate < 2% AND p99 latency < 2x v4 baseline
- Hold: v5 metrics 在 threshold 边缘（1-2% error rate 或 1.5-2x latency）— investigate before proceeding
- Rollback: v5 error rate > 2% OR p99 > 2x sustained 5+ minutes OR critical failure

## Rollback drill（at least once during 24h monitoring）

**Trigger criteria:** any of:
- v5 error rate **> 2%** sustained 5+ minutes
- v5 p99 latency **> 2x** v4 p99 baseline sustained 5+ minutes
- Critical path failure (auth / core API endpoints return 5xx)

**Rollback procedure:**
1. Change load balancer / gateway config: route 100% of traffic back to v4
2. Verify v4 is healthy (curl health endpoint, sample real traffic)
3. Pause v5 traffic (set v5 to 0%, leave v5 process running for diagnostics)
4. Capture rollback time: from trigger to v4=100%
5. File incident: `.blackboard/incidents/<ISO>-r10-rollback.md`

**Owner records:**
```

  trigger time: <ISO>
  trigger reason: <reason>
  rollback start: <ISO>
  rollback complete (v4=100%): <ISO>
  total rollback time: <seconds>
  v5 error rate at trigger: <%>
  v4 verified serving 100% after rollback: yes/no
  issues encountered: <description>
```
