# R10.3 Simplified Cutover Runbook（2026-08-13）

> **Operator scope.** Owner (user) executes the cutover. AI cannot run scripts that touch systemd / wechat-iLink.
> **Updated 2026-08-13** — original 7-day traffic-shifting runbook was based on a load-balancer model that doesn't apply to v5. v5 is a personal AI butler per ADR-0001 ("部署目标为单机自托管"). Cutover is a 5-10 minute stop-and-restart on a single host.

## v5 / v4 部署现状

| | v4（当前）| v5（目标）|
|---|---|---|
| 部署形态 | systemd user services | systemd user service（`butler-v5-gateway.service`）|
| Runtime | `python3 -m butler.main` (v4.0.0) | `pnpm dev` (v5.0.0) |
| 微信 iLink | `butler-gateway.service`（PID 998，跑着）| `apps/wechat-gateway` Phase 3 stub（**未实接 iLink**）|
| HTTP API | （无 HTTP endpoint）| `apps/api` port 3000 + `/healthz` |
| Health check | `ps -ef \| grep butler.main` | `curl http://127.0.0.1:3000/healthz` |
| Port | （无）| 3000 |

**Scope 警告**：v5 还没实接 wechat iLink（Phase 3 stub）。切到 v5 后 wechat 消息会断流，**除非** user 主动把 v4 的 iLink 凭证 / 状态迁到 v5 stub —— 这不在本 R10.3 scope。

## Pre-cutover checklist

- [ ] **commit `7aedf763`+ 已 push 到 origin main**（settings.json schema + v4 cli rot 已修；v5 cutover 脚本在本地）
- [ ] **`.env` 已配置 v5 需要的 LLM provider keys**（Anthropic / OpenAI / 等；参考 `butler-v5/.env.example`）
- [ ] **v5 本地 dry-run 过一次**：`cd butler-v5 && pnpm dev`，访问 `http://127.0.0.1:3000/healthz` 返回 200
- [ ] **v4 状态已 snapshot**（v5 不行时 rollback 起点）：`systemctl --user list-units --type=service --state=active --nolegend | grep butler-` 记录当前 active 列表
- [ ] **可选**：commit `.env` 不在 repo，所以 v5 启动后第一件事是 source 自己的 `.env`（docker compose 自动；systemd 走 `EnvironmentFile`）

## Step 1: 启动 v5（5-10 分钟）

```bash
# 1. 跑切换脚本
cd /home/ailearn/projects/WFXM
bash butler-v5/scripts/cutover/v5-switch.sh
```

脚本会：
1. Snapshot 当前 active 的 v4 butler services
2. Stop 所有 `butler-*.service`（v4 gateway + runtime + morning-brief + push-drain + cadence 等）
3. `docker compose up -d postgres wechat-mock`（v5 依赖）
4. `nohup pnpm dev` 启动 v5 wiring（port 3000，日志到 `/tmp/butler-v5.log`）
5. 轮询 `http://127.0.0.1:3000/healthz` 60 秒内等 200
6. 失败自动 rollback（调 v5-rollback.sh）

预期输出：
```
[v5-switch] === R10.3 v5-switch (simplified) ===
[v5-switch] v4 services currently active:
[v5-switch]   butler-gateway.service
[v5-switch]   butler-morning-brief.service
[v5-switch]   ...
[v5-switch] Stopping v4 services...
[v5-switch] v5 wiring: pid=12345 listening on :3000
[v5-switch] v5 healthy after 12s
[v5-switch] === v5 switch complete ===
```

## Step 2: 验证 v5 满足需要（5-30 分钟）

```bash
# 监控 v5 日志
tail -f /tmp/butler-v5.log

# 健康检查（应该一直 200）
watch -n 5 'curl -sS http://127.0.0.1:3000/healthz | jq'

# 看 v5 wiring 实际跑了什么端口
ss -tlnp | grep :3000

# 看 v5 是否能起来 wechat-gateway stub
ps -ef | grep -E "wechat-gateway|butler start" | grep -v grep
```

**v5 满足条件**：
- `/healthz` 持续 200
- v5 路由 (`apps/api/src/routes.ts`) 接受 POST `/v1/conversations` 等 endpoint
- v5 启动后 user 用 dev tools (`butler start` 之类) 能调通

**v5 暂时不满足**：
- wechat iLink 没接（Phase 3 stub）—— 这是已知 R10+ scope

## Step 3: 决策 proceed / hold / rollback

| Decision | 触发条件 | 操作 |
|---|---|---|
| **proceed → v5 永久切换** | v5 满足你期望，wechat 暂时断可接受 | Step 4 |
| **hold（保留 v4 跑，v5 试跑）** | 想用 v5 试试但不 commit | 停 v5 + 重启 v4（Step 5 rollback）|
| **rollback → v4** | v5 出问题、v5 wechat stub 不可接受、v5 跑不通 | Step 5 |

## Step 4: v5 永久切换（如果 proceed）

```bash
# 1. 保存 systemd unit 文件
mkdir -p ~/.config/systemd/user
cp /home/ailearn/projects/WFXM/butler-v5/scripts/cutover/butler-v5-gateway.service \
   ~/.config/systemd/user/

# 2. 创建 v5 env file（按 .env.example 填 ANTHROPIC_API_KEY 等）
mkdir -p ~/.config/butler-v5
# 把现有 ~/.env 内容复制过去，去掉 v4 独有项
# 或者：cp /home/ailearn/projects/WFXM/.env ~/.config/butler-v5/env

# 3. 重载 systemd + 启用 v5 服务
systemctl --user daemon-reload
systemctl --user disable butler-gateway.service butler-runtime-lingwen.service
systemctl --user enable --now butler-v5-gateway.service

# 4. 验证
systemctl --user status butler-v5-gateway.service
curl -sS http://127.0.0.1:3000/healthz
```

## Step 5: Rollback 到 v4（如果不想切 v5）

```bash
cd /home/ailearn/projects/WFXM
bash butler-v5/scripts/cutover/v5-rollback.sh
```

脚本会：
1. Kill v5 dev process（port 3000 listener + pnpm dev / tsx 进程）
2. 重启所有 v4 butler services（gateway / runtime / morning-brief / push-drain / cadence 等）
3. 验证 v5 已 down（`/healthz` 不可达）

预期：
- 10 秒内 v4 gateway 恢复（PID 998 类，重新跑）
- 微信 iLink 重新连接
- v5 端口 3000 关闭

## Success criteria（R10.3 closure）

R10.3 closes when：
- v5 切换脚本 + rollback 脚本在 repo 落地
- owner 至少跑过一次 v5-switch.sh（无论结果 proceed / hold / rollback）
- shift card 016 + 015-preflight 反映 v5 cutover owner decision
- （可选）`butler-v5-gateway.service` 在 owner 系统上 enable

R10.3 完全 AI-side 不需要再操作。R10.4 incremental closure：owner commit v5-switch / v5-rollback 结果数据后通知我。

## Known issues（user 决策）

1. **v5 wechat-gateway 是 Phase 3 stub** —— v5 切了 wechat 消息会断；要么完成 Phase 3+，要么接受断流
2. **v5 没有 ops cadence / morning-brief 等 v4 cron service 对应** —— 这些 v4 service 切了后 v5 不会跑；要么 v5 实现，要么 owner 手动跑
3. **`butler-b9-weekly-gate.service` 跑 v4 学习流程** —— 切 v5 后 v5 还没实现；要么 v5 实现，要么保留 v4 service 但禁用
4. **v5 启动依赖 docker（postgres）** —— 如果 owner 不在 docker 环境，需要改造
5. **v4 状态完整恢复 = `systemctl --user start` v4 services** —— 验证 rollback 真的能用

R10.x plan 阶段（v4 standby 3 天后启动）会正式 decommission v4 这些 service。
