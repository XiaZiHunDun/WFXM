## 2. 候选清单

### C1 自然语言提醒 / 个人定时任务（推荐 ★★★）

**用户场景**：微信里直接说「明天 9:30 提醒我交周报」「每周一早上发我上周任务摘要」
「取消周三的提醒」。

**现状缺口**：Schedule 已支持周期/单次触发，但 job 只能通过
`config/schedule-jobs.json` 或 `BUTLER_V5_SCHEDULE_JOBS` 配置
（[`schedule-config.ts`](../../../apps/api/src/schedule-config.ts)），聊天里无法创建；
`/待办` 是 task，不是到点提醒。

**方案要点**：

- 新增 reminder 持久化（复用 schedule job 字段 + owner 维度），提供
  `create_reminder / list_reminders / cancel_reminder` 三个低风险工具；
- 单次与 daily/weekly 重复；固定 `Asia/Shanghai`；每人上限（如 20 条）；
- 到点走现有 schedule worker → 微信出站；纯文本提醒不触发副作用能力；
- 幂等键：`reminderId + fireAt`；重启后从持久化恢复。

**成功判据**：

1. 一句话创建后，回复包含「已设置 + 时间 + 内容」；
2. 到点 ±60s 内推送；取消后不再推送；
3. 重启进程后提醒仍在；
4. 时间表达不明确时只追问一次，不猜测。

**失败可见性**：解析不出时间 → 明确回「请给出具体时间（如 明天 9:30）」；
创建/取消失败 → 原因可读；漏发 → audit 记 `reminder.missed`，`/提醒` 可查状态。

**回滚**：`BUTLER_V5_REMINDERS_ENABLED` 默认 `0`；关闭后工具不注册，已有数据保留。

**差异化**：从「你问我答」升级为「到点主动记得」，是管家心智的核心；且完全复用现有
schedule + outbox，不需要新外部依赖。

### C2 审批前预览：diff / 命令全文（推荐 ★★★）

**用户场景**：收到审批时直接看到「将对 `demo-note.txt` 做哪些改动」或「将执行的完整
命令与工作目录」，再决定确认或拒绝。

**现状缺口**：审批文案只给「需要修改文件 X，请确认」
（[`types.ts`](../../../packages/domain/src/governance/types.ts) `approvalQuestion`），
`digest` 里其实已有参数，但没有以可读形式展示给 owner。

**方案要点**：

- 审批通知渲染增强：`write_file` 输出相对路径 + 增删行摘要（新旧内容对比，超限截断）；
  `run_command` 输出命令全文 + cwd；其他能力回退现有文案；
- owner `/v1/owner/approvals` 增加 `preview` 字段，供 demo / 未来 UI 使用；
- 路径相对化、凭证字段脱敏；不改变审批状态机与授权模型。

**成功判据**：

1. 审批消息能看到 diff 或命令全文；
2. 超长内容截断并标注「已截断」；
3. 批准 / 拒绝 / 过期行为与现在完全一致；
4. 预览生成失败时回退旧文案，不阻断审批。

**失败可见性**：预览渲染异常 → 旧文案 + 日志；不得出现内部工具名或绝对路径。

**回滚**：`BUTLER_V5_APPROVAL_PREVIEW` 默认 `0`，关闭即回退旧文案。

**差异化**：把「安全」变成 owner 能看见的东西；直接降低误批概率，且不动已冻结的
trust mode 决策。

---

### C3 每周项目周报 / 主动巡检（推荐 ★★）

**用户场景**：每周一早上自动收到一条摘要：上周完成了什么、还剩哪些待办、失败/审批
多少次；也可手动发 `/周报`。

**现状缺口**：schedule MVP 可跑只读巡检，task digest 有 1h throttle
（[`wechat-run-notify.ts`](../../../apps/api/src/wechat-run-notify.ts)），但没有
「跨任务 + 审计 + 用量」的组合周报。

**方案要点**：

- 新增 `weekly-digest` job 模板：只读查询 tasks / runs / audit / usage，渲染单条微信；
- 默认关闭，owner 可配置星期与时间；空周不打扰（quietSuccess）；
- 手动 `/周报` 复用同一渲染函数，不产生第二套逻辑。

**成功判据**：

1. 周报包含完成、待办、失败、审批四项数字；
2. 数字与 `/tasks`、`/audit`、`/usage` 一致；
3. 空周不推送；
4. 手动 `/周报` 与自动推送内容结构一致。

**失败可见性**：查询失败 → 回「周报生成失败：<原因>」并记 audit；缺数据 → 标注「无数据」。

**回滚**：删除 job / 关闭 `BUTLER_V5_SCHEDULE_ENABLED` 即停。

**差异化**：让 owner 感到「被托管」，而不是每次主动问；同时验证 schedule + 审计链路。

---

### C4 入站图片 / 文件理解（备选，暂不推荐）

**用户场景**：发截图或 PDF，直接总结 / 提取待办 / 落入项目知识。

**现状缺口**：document ingest 仅文本类；图片 OCR、向量索引明确延后
（[`v5-post-boundary-roadmap-2026-08.md`](v5-post-boundary-roadmap-2026-08.md) §P4）。

**为什么暂不推荐**：需要 OCR / 多模态能力与外部依赖，成本与不确定性最高，且当前没有
owner 痛点的实证；建议等 C1–C3 后再评估。

## 3. 推荐组合

| 顺序 | 选点 | 理由 | 预估范围 |
|------|------|------|----------|
| 1 | C1 自然语言提醒 | 最高频、心智最强、复用 schedule | 新增 store + 3 工具 + 测试 |
| 2 | C2 审批前预览 | 直接降低误批、改动集中 | 审批渲染 + owner 字段 + 测试 |
| 3 | C3 每周周报 | 复用 C1 的定时地基 | job 模板 + 渲染 + `/周报` |

三者互不冲突，C1 先做可为 C3 铺路；每个都可独立开关、独立回滚。
